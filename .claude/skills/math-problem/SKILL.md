# 수능 스타일 수학 문제 생성 파이프라인

이 스킬은 3개의 subagent를 오케스트레이션하여 수능/평가원 격식의 수학 문제를 한 문항 생성합니다.

## 사용자 입력 파싱
사용자 메시지에서 다음을 추출하세요 (선택 사항, 없으면 리더가 결정):
- 단원 (수학Ⅰ / 수학Ⅱ / 미적분 중 하나, 또는 세부 단원명)
- 문제 번호 (1~30번)
- 난이도 (쉬움 / 중간 / 킬러)
- 답 형식 (5지선다 / 단답형)

확률통계/기하는 이 스킬의 범위 밖입니다. 요청되면 거절하고 범위를 안내하세요.

## 파이프라인 실행 절차

### Step 1. 리더 호출 (1회)
`Task` 도구로 `math-problem-leader` subagent를 호출하여 설계 브리프를 받습니다.

호출 프롬프트 템플릿:
```
사용자가 다음과 같이 요청했습니다:
"<사용자 원문>"

추출된 명시 조건:
- 단원: <없으면 "지정 없음">
- 문제 번호: <없으면 "지정 없음">
- 난이도: <없으면 "지정 없음">
- 답 형식: <없으면 "지정 없음">

`.claude/skills/math-problem/references/` 의 자료를 참조하여 설계 브리프를 작성해 주세요.
```

받은 출력을 `BRIEF` 변수처럼 보관하고, 이후 모든 루프에서 동일하게 사용합니다.

### Step 2. 제작–검토 루프 (최대 5회)

루프 변수:
- `best_score = 0.0`
- `best_problem = null`
- `best_review = null`
- `iteration = 1`
- `last_feedback = ""` (1회차에는 비어 있음)

각 루프에서:

**Step 2a. 제작자 호출** — `Task`로 `math-problem-creator` 호출. 매번 새 인스턴스(자동).

호출 프롬프트 템플릿:
```
설계 브리프:
---
<BRIEF 전문>
---

이전 시도 피드백 (있다면):
---
<last_feedback, 1회차에는 "없음 (첫 시도)">
---

위 브리프대로 한 문항을 완성해 주세요.
```

**Step 2b. 검토자 호출** — `Task`로 `math-problem-reviewer` 호출. 매번 새 인스턴스.

호출 프롬프트 템플릿:
```
설계 브리프:
---
<BRIEF 전문>
---

제출된 문제:
---
<제작자가 방금 출력한 전문>
---

채점 기준에 따라 객관적으로 평가해 주세요.
```

**Step 2c. 점수 파싱 및 의사결정**

검토자 출력에서 정규식 `최종 점수:\s*([0-9]+\.?[0-9]*)/10` 으로 점수를 추출.

- `score > best_score` 이면 `best_*` 갱신.
- `score >= 9.0` 이면 **즉시 루프 종료**, Step 3으로 진행.
- 그렇지 않고 `iteration < 5` 이면:
  - 검토자 출력의 "다음 루프 제작자에게 전달할 피드백" 섹션을 추출하여 `last_feedback`에 저장.
  - `iteration += 1`, Step 2a로.
- `iteration == 5`이면 루프 종료, Step 3으로.

### Step 3. 최종 결과 반환

사용자에게 다음 형식으로 응답:

```
# 수능 스타일 수학 문제 (시도 N회, 최고점 X.X/10)

## 설계 브리프 요약
- 단원: ...
- 문제 번호: ...
- 핵심 발상: ...

---

<best_problem 전문>

---

## 검토 요약
<best_review에서 강점·약점·점수 요약>

(9.0/10 미달인 경우)
> 5회 시도 안에 9.0/10에 도달하지 못했습니다. 위 결과는 최고점(X.X/10) 시도입니다. 더 정교한 결과가 필요하면 단원/번호/제약을 더 좁혀 다시 요청해 주세요.
```

## 중요 규칙

1. **각 루프에서 제작자·검토자는 반드시 새로 호출**합니다. 한 번 호출한 Task는 자동으로 격리되므로 별도 조치 불필요.
2. **리더는 1회만 호출**합니다. 루프 안에서 다시 부르지 마세요.
3. 제작자와 검토자가 같은 답을 도출하지 못해 점수가 0점에 가깝다면, 피드백을 그대로 다음 루프에 전달하세요. 제작자가 더 안전한 발상으로 우회합니다.
4. **시간 낭비 방지**: 루프 안에서 사용자에게 중간 결과를 보여줄 필요는 없습니다. 매 루프 사이에 한 줄 진행 메시지(예: "시도 2/5 — 직전 점수 7.5/10") 정도만 출력하고, 최종 결과만 풍부하게 보여주세요.
5. 사용자가 "범위 외" 단원(확률통계/기하 등)을 요청하면 파이프라인을 시작하지 않고 거절합니다.
