# 수능 스타일 수학 문제 생성 파이프라인

이 스킬은 3개의 subagent를 오케스트레이션하여 수능/평가원 격식의 수학 문제를 한 문항 생성합니다. **누적 학습 노트**와 **베이스라인 폴백**을 통해 5회 루프 안에서 점수를 단조 증가시키도록 설계되어 있습니다.

## 사용자 입력 파싱
사용자 메시지에서 다음을 추출하세요 (선택 사항, 없으면 리더가 결정):
- 단원 (수학Ⅰ / 수학Ⅱ / 미적분 중 하나, 또는 세부 단원명)
- 문제 번호 (1~30번)
- 난이도 (쉬움 / 중간 / 킬러)
- 답 형식 (5지선다 / 단답형)

확률통계/기하는 이 스킬의 범위 밖입니다. 요청되면 거절하고 범위를 안내하세요.

## 파이프라인 실행 절차

### Step 1. 리더 호출 (1회)
`Task` 도구로 `math-problem-leader` subagent를 호출하여 설계 브리프를 받습니다.

호출 프롬프트 템플릿:
```
사용자가 다음과 같이 요청했습니다:
"<사용자 원문>"

추출된 명시 조건:
- 단원: <없으면 "지정 없음">
- 문제 번호: <없으면 "지정 없음">
- 난이도: <없으면 "지정 없음">
- 답 형식: <없으면 "지정 없음">

`.claude/skills/math-problem/references/` 의 자료(units, difficulty, patterns, examples, anti-patterns)를 모두 참조하여 설계 브리프를 작성해 주세요.
```

받은 출력을 `BRIEF` 변수처럼 보관하고, 이후 모든 루프에서 동일하게 사용합니다.

### Step 2. 제작–검토 루프 (최대 5회)

루프 변수:
- `best_score = 0.0`
- `best_problem = null`
- `best_review = null`
- `best_iteration = 0`
- `iteration = 1`
- `last_feedback = ""` (1회차에는 비어 있음)
- `learning_notes = []` (누적 핵심 결함과 수정안의 리스트. 매 루프 검토 후 append)
- `consecutive_no_improvement = 0` (조기 종료 카운터)

각 루프에서:

**Step 2a. 제작자 호출** — `Task`로 `math-problem-creator` 호출. 매번 새 인스턴스(자동).

호출 프롬프트 템플릿:
```
설계 브리프:
---
<BRIEF 전문>
---

직전 시도 + 검토 피드백 (있다면):
---
<last_feedback, 1회차에는 "없음 (첫 시도)">
---

누적 학습 노트 (1~N회 검토자가 지적한 모든 핵심 결함과 수정안):
---
<learning_notes 전문. 비어 있으면 "없음 (첫 시도)">
---

베이스라인 문제 (현재까지 최고점):
---
<best_problem 전문 + "점수 N.N/10". best_problem이 null이면 "없음 (첫 시도)">

베이스라인 사용 지침:
- 현재 시도가 직전보다 점수가 낮을 가능성이 있을 때: 위 베이스라인 구조를 시작점으로 두고 검토자가 지정한 부분만 변형하세요.
- 직전 시도가 베이스라인이라면: 직전 피드백의 "구체 수정안 3개"를 우선 적용하되, 본질 함수 형태는 베이스라인을 유지.
- 베이스라인이 없으면(1회차): 브리프에 충실하게 처음부터 설계.
---

위 자료를 모두 검토한 뒤 `.claude/skills/math-problem/references/anti-patterns.md`의 8개 체크 항목을 모두 통과시키고 한 문항을 완성해 주세요. 반드시 2-Phase 출력(내부 검증 보고서 → 잠금 → 본문).
```

**Step 2b. 검토자 호출** — `Task`로 `math-problem-reviewer` 호출. 매번 새 인스턴스.

호출 프롬프트 템플릿:
```
설계 브리프:
---
<BRIEF 전문>
---

제출된 문제:
---
<제작자가 방금 출력한 전문 (내부 검증 보고서 포함)>
---

채점 기준에 따라 객관적으로 평가해 주세요. 반드시 "최종 점수: X.X/10" 형식 + "핵심 결함 / 구체 수정안 3개 / 베이스라인 권장" 3-섹션 피드백.
```

**Step 2c. 점수 파싱 및 학습 노트 누적**

검토자 출력에서 정규식 `최종 점수:\s*([0-9]+\.?[0-9]*)/10` 으로 점수를 추출.

- `score > best_score` 이면 `best_*` 갱신(`best_iteration = iteration` 포함), `consecutive_no_improvement = 0`.
- 그렇지 않으면 `consecutive_no_improvement += 1`.
- 검토자 출력에서 "핵심 결함" 1줄과 "구체 수정안" 3줄을 추출하여 `learning_notes`에 `{iter: N, score: X.X, key_flaw: "...", fixes: ["...", "...", "..."]}` 형태로 append.

**Step 2d. 종료 조건**

다음 중 하나라도 만족하면 루프 종료, Step 3으로 진행:

1. `score >= 9.0` (성공)
2. `iteration == 5` (최대 시도 소진)
3. `consecutive_no_improvement >= 2` AND `iteration >= 3` (조기 종료: 연속 2회 점수 개선 없음. 다른 발상이 필요할 가능성 — 사용자에게 브리프 재정의 권장)

종료 조건 미충족 시 `iteration += 1`, Step 2a로.

루프 진행 메시지(매 루프 사이):
- 형식: "시도 N/5 — 점수 X.X/10 (최고 Y.Y/10, 핵심 결함: [한 줄])"
- 중간 결과 본문은 사용자에게 노출하지 말 것 (최종 결과만 풍부하게).

### Step 3. 최종 결과 반환

사용자에게 다음 형식으로 응답:

```
# 수능 스타일 수학 문제 (총 N회 시도, 최고점 X.X/10, 시도 M에서 달성)

## 설계 브리프 요약
- 단원: ...
- 문제 번호: ...
- 핵심 발상: ...

---

<best_problem 전문>

---

## 검토 요약 (시도 M)
<best_review에서 강점·약점·점수 요약>

## 시도별 점수 추이
| 시도 | 점수 | 핵심 결함 (한 줄) |
|---|---|---|
| 1 | X.X | ... |
| 2 | X.X | ... |
| ... | ... | ... |

(9.0/10 미달 시)
> 5회(또는 조기 종료 N회) 시도 안에 9.0/10에 도달하지 못했습니다. 최고점은 시도 M의 X.X/10입니다. 
> 다음 중 하나를 시도해 보세요:
> - 단원/번호/제약을 더 좁혀 다시 요청
> - 누적 학습 노트가 가리키는 본질 결함(예: AP-4 영역 부정합)을 우회하도록 단원 선택 조정
> - 검토자 채점 기준은 동결되어 있으므로, 7~8점대 결과를 그대로 활용 가능.
```

## 중요 규칙

1. **각 루프에서 제작자·검토자는 반드시 새로 호출**합니다. Task는 자동 격리되므로 별도 조치 불필요.
2. **리더는 1회만 호출**합니다. 루프 안에서 다시 부르지 마세요.
3. **누적 학습 노트는 매 루프 모두 전달** (직전 한 회만 X). 5회까지 갈수록 노트가 길어져도 그대로 전달.
4. **베이스라인 폴백**: 점수가 후퇴하기 시작하면 다음 호출에서 best_problem 구조를 명시적으로 시작점으로 지정. 제작자가 새 발상에 매번 도전하다 모두 실패하는 것을 방지.
5. **조기 종료**: 연속 2회 개선 없으면 (iteration ≥ 3에서) 종료. 5회 강제 소진은 토큰 낭비.
6. **시간 낭비 방지**: 루프 안 중간 결과 본문은 노출 X. 한 줄 진행 메시지만.
7. 사용자가 "범위 외" 단원(확률통계/기하 등)을 요청하면 파이프라인 시작 없이 거절.

## 디버깅 가이드 (스킬이 잘 작동하지 않을 때)

- **모든 시도가 3점대 이하**: 브리프 자체가 비현실적일 수 있음. 리더 재호출보다는 사용자에게 단원/난이도 재정의 요청.
- **모든 시도가 AP-1(π 무리수) 위반**: 리더 브리프의 "π 소거 전략" 섹션이 명확한지 점검. 삼각함수 합성을 회피하는 단원으로 변경 권유.
- **모든 시도가 AP-4(영역 부정합) 위반**: 미적분에서 다항으로 후퇴하는 패턴. 브리프의 "미적분 고유 개념 사용 위치"를 더 강제적으로 작성하도록 리더 재설계 고려.
- **점수가 6~7점에서 정체**: 검토자 채점 기준 동결로 인한 자연스러운 천장. 사용자에게 7점대 결과 활용을 제안.
